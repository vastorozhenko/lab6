# ЛР №6. Безпечний клієнт-серверний застосунок з SSL/TLS

Клієнт і сервер на Python (asyncio + ssl). Обмін: TLS-рукостискання → автентифікація логін/пароль (bcrypt) → токен сесії → повідомлення з HMAC-SHA256 → відповідь сервера з HMAC. Сервер веде JSON-журнал `logs/server.jsonl`, скрипт `analyze_logs.py` шукає нетипові випадки.

## Вимоги
- Python 3.11+ (перевірено на Ubuntu 24.04, Python 3.12)
- OpenSSL (для генерування сертифікатів)
- `pip install -r requirements.txt`

## Кроки
```bash
# 0) Сертифікати: локальний CA -> сертифікат сервера (CN=localhost, SAN: localhost, 127.0.0.1)
bash scripts/gencerts.sh

# 1) Сервер (окремий термінал)
python server.py --host 127.0.0.1 --port 8443 --cert certs/server.crt --key certs/server.key --ca certs/ca.crt

# 2) Клієнт
python client.py --host 127.0.0.1 --port 8443 --ca certs/ca.crt --user alice --password secret --msg "hello TLS"

# 3) Аналіз журналу
python analyze_logs.py logs/server.jsonl
```

Тестові користувачі `alice` і `bob`, пароль `secret`. У `users.json` зберігаються лише хеші bcrypt (cost 12).

Опційно mTLS: сервер з `--require-client-cert`, клієнт з `--cert certs/client.crt --key certs/client.key`.

## Події журналу

| Подія | Коли |
|---|---|
| `tls.handshake` | успішне TLS-рукостискання (версія, шифр) |
| `tls.fail` | невдале рукостискання (клієнт відхилив сертифікат, не-TLS з'єднання, немає клієнтського сертифіката при mTLS) |
| `auth.ok` / `auth.fail` | вхід успішний / неуспішний (`reason`: invalid або locked, номер спроби) |
| `auth.locked` | 3 невдалі спроби поспіль: користувача заблоковано на 60 с |
| `data.ok` | повідомлення прийнято (користувач, розмір у байтах) |
| `data.bad_hmac` / `data.invalid_token` | HMAC не збігся / недійсний токен |
| `conn.error` / `conn.closed` | помилка обробки / з'єднання закрито |

Паролі, токени й HMAC-ключ у журнал не записуються.

## Зміни відносно демо-пакета
1. Хеш у `users.json` не відповідав паролю `secret`, тому вхід завжди був невдалим. Хеші згенеровано заново (bcrypt).
2. Сервер генерував випадковий HMAC-секрет при кожному запуску, а клієнт використовував демо-секрет, тому кожне повідомлення відхилялося з `bad_hmac`. Сервер тепер використовує той самий демо-секрет (або `--shared-hmac`).
3. TLS-рукостискання перенесено в обробник з'єднання (`start_tls`), щоб невдалі рукостискання записувалися в журнал (`tls.fail`); раніше вони не потрапляли в журнал.
4. Клієнт виводить дані сертифіката сервера, перевіряє HMAC відповіді, коректно повідомляє про помилку сертифіката і не падає з помилкою SSL під час закриття з'єднання.
5. Додано демо-політику блокування (3 спроби → 60 с) і видалення токена після закриття з'єднання.
6. Сертифікат CA доповнено розширенням keyUsage: Python 3.13+ без нього відхиляє ланцюжок.
7. `analyze_logs.py`: групування невдалих входів за IP без порту, вивід невдалих рукостискань, блокувань і попереджень про повторювані помилки входу.
